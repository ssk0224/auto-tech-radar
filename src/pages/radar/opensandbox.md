# OpenSandbox: 概要と革新性

OpenSandboxは、AIエージェント向けに設計された、セキュア、高速、かつ拡張可能なサンドボックスランタイムです。AIアプリケーションがコード実行、コマンド実行、ファイル管理、ブラウザ/デスクトップ操作を隔離された環境で実行することを可能にします。Dockerでのローカル開発からKubernetesへのデプロイメントまで、統一されたサンドボックスAPIを通じてシームレスな運用を提供します。

本プロジェクトは、OpenSSF Best PracticesおよびCNCF Landscapeに掲載されており、その信頼性とコミュニティにおける重要性が示されています。

主要機能は以下の通りです。

*   **Fast Sandbox runtime**: Firecrackerベースの高速かつ高密度なサンドボックス実行環境。64 ms P50 (シリアル) / 125.4 ms P99 (10並行) の起動性能を誇り、メモリとディスク状態を保持した一時停止/再開をサポートします。
*   **Agent working environments**: エージェントがコード実行、コマンド実行、ファイル管理を行うための組み込みAPIを提供し、コーディングエージェント、ブラウザ、デスクトップのサンドボックス内実行を可能にします。
*   **Network access control**: 統一されたイングレスゲートウェイによるインバウンドトラフィックルーティングと、サンドボックスごとのエグレスポリシーによるアウトバウンドアクセス制御を実現します。
*   **Credential Vault**: エージェントが外部サービスを呼び出す際に、実際の認証情報をサンドボックスワークロードに公開することなく安全に利用できるメカニズムを提供します。
*   **Local to cluster**: Dockerでのローカル開発からKubernetesへのデプロイメントまで、統一されたライフサイクルAPIを提供。リソースプールとバッチ作成により、エージェント評価や強化学習（RL）トレーニングワークロードをサポートします。
*   **SDKs, CLI, and MCP**: Python, Java/Kotlin, TypeScript/JavaScript, C#/.NET, Go向けのSDK、ターミナルCLI (`osb`)、およびMCP (Multi-Agent Communication Protocol) を通じたエージェント接続をサポートします。
*   **Extensible sandbox protocol**: 定義されたサンドボックスライフサイクルおよび実行APIに基づき、カスタムランタイム統合を構築するための拡張性を提供します。

## 解決する主要な課題とアーキテクチャ

### 従来の技術スタックにおける問題点

AIエージェントが自律的にコードを実行したり、外部リソースにアクセスしたりする際、以下の課題が顕在化します。

1.  **セキュリティリスク**: エージェントがホストシステムに直接アクセスしたり、機密情報を含む環境で実行されたりすると、悪意のあるコード実行や情報漏洩のリスクが高まります。特に、生成AIが生成したコードの安全性を保証することは困難です。
2.  **環境の分離と一貫性**: 複数のAIエージェントが同時に動作する場合、互いの環境に影響を与えたり、依存関係の競合が発生したりする可能性があります。また、エージェントの評価やトレーニングにおいて、毎回クリーンで一貫した環境を迅速にプロビジョニングすることが課題となります。
3.  **パフォーマンスとリソース効率**: 従来の仮想マシン（VM）は起動に時間がかかり、リソース消費も大きいため、多数のAIエージェントを並行して実行する際のボトルネックとなります。コンテナは軽量ですが、カーネル共有によるセキュリティ上の懸念が残ります。
4.  **資格情報の管理**: AIエージェントが外部APIやサービスを利用する際、APIキーや認証情報を安全に管理し、サンドボックス環境に漏洩させずに利用させるメカニズムが不足しています。
5.  **開発からデプロイメントへの移行**: ローカルでの開発環境と本番環境（特にKubernetesのような分散環境）でのサンドボックスの管理・運用に一貫性がなく、移行プロセスが複雑になりがちです。

### 本ツールが採用するアプローチと仕組み

OpenSandboxはこれらの課題に対し、以下の技術的アプローチとアーキテクチャで解決策を提供します。

1.  **マイクロVMベースのサンドボックス化 (Firecracker)**:
    *   OpenSandboxのコアは、AWSが開発した軽量仮想化技術であるFirecrackerを基盤としています。これにより、従来のVMよりもはるかに高速な起動（P50で64ms）と、コンテナよりも高いセキュリティ分離（カーネルレベルでの分離）を両立します。
    *   各AIエージェントは完全に隔離された専用のマイクロVM内で動作し、ホストシステムや他のエージェントへの影響を最小限に抑えます。
    *   サンドボックスの一時停止/再開機能により、メモリとディスクの状態を保持したまま環境をフリーズ・再開できるため、エージェントの評価や強化学習における環境リセットのオーバーヘッドを大幅に削減します。

2.  **統一されたサンドボックスAPIと制御プレーン**:
    *   OpenSandboxは、サンドボックスの作成、実行、ファイル操作、ネットワーク制御などを抽象化する統一されたAPIを提供します。
    *   このAPIは、Dockerでのローカル開発環境からKubernetesクラスターへの大規模デプロイメントまで一貫して利用可能です。Kubernetesオペレーターを通じて、リソースプール管理やサンドボックスのバッチ作成を効率的に行い、大規模なエージェントワークロードをサポートします。

3.  **エージェント向けの高レベルAPI**:
    *   サンドボックス内でコマンドを実行したり、ファイルを読み書きしたり、コードを実行したりするための直感的なAPIをSDK経由で提供します。これにより、AIエージェントが開発タスク、データ分析、Webオートメーション（Playwright/Chrome統合）などを安全に実行できます。

4.  **厳格なネットワークアクセス制御**:
    *   統一されたイングレスゲートウェイを通じて、サンドボックスへのインバウンドトラフィックを管理します。
    *   サンドボックスごとにカスタマイズ可能なエグレスポリシーにより、アウトバウンドトラフィックを細かく制御し、エージェントが許可された外部サービスのみにアクセスできるようにします。

5.  **Credential Vaultによる安全な資格情報管理**:
    *   エージェントが外部サービスにアクセスする際に必要なAPIキーや認証情報を、サンドボックス環境に直接公開することなく、安全に注入・利用できるCredential Vault機能を提供します。これにより、機密情報の漏洩リスクを大幅に低減します。

6.  **マルチ言語対応と拡張性**:
    *   Python, Java/Kotlin, TypeScript/JavaScript, C#/.NET, Goなど、主要なプログラミング言語向けのSDKを提供し、幅広い開発者がOpenSandboxを容易に統合できるようにします。
    *   CLIツール `osb` は、サンドボックスのライフサイクル管理や診断をコマンドラインから直接行えるようにします。
    *   MCP (Multi-Agent Communication Protocol) のサポートにより、Claude CodeやCursorのようなMCP対応クライアントとの連携も可能です。
    *   サンドボックスのライフサイクルおよび実行APIは公開されており、カスタムランタイムや特定の要件に合わせた拡張が可能です。

### 解決する主要な課題とアーキテクチャ

#### 従来の技術スタックにおける問題点

AIエージェントが自律的に動作し、コード生成や実行、外部ツール連携を行う現代のワークフローにおいて、以下の課題が顕在化しています。

1.  **セキュリティリスク**: AIエージェントが生成したコードや、外部から取得したスクリプトを直接ホスト環境で実行することは、システムへの不正アクセス、データ破壊、情報漏洩といった重大なセキュリティリスクを伴います。特に、未知のコードを実行する際の安全な隔離メカニズムが不可欠です。
2.  **環境の一貫性と再現性**: エージェントの評価、デバッグ、または強化学習のトレーニングにおいて、毎回クリーンで一貫性のある実行環境を迅速にプロビジョニングすることが求められます。従来のコンテナやVMでは、起動時間やリソース消費のオーバーヘッドが大きく、効率的な反復実行を妨げます。
3.  **リソース管理とスケーラビリティ**: 大規模なAIエージェント群を運用する際、各エージェントに適切なリソースを割り当て、効率的にスケールアウトさせる必要があります。特に、多数の独立した実行環境を低遅延で提供し、かつ高密度にデプロイすることは困難です。
4.  **資格情報の安全な管理**: AIエージェントが外部のAPIやサービス（例: クラウドサービス、データベース）と連携する際、認証情報（APIキー、トークンなど）をサンドボックス環境に直接公開することなく、安全に利用させるメカニズムが必要です。
5.  **開発から本番へのデプロイメントの複雑性**: ローカルでの開発・テスト環境と、Kubernetesのような本番クラスター環境でのサンドボックスの管理・運用に一貫性がなく、デプロイメントパイプラインが複雑化する傾向があります。

#### 本ツールが採用するアプローチと仕組み

OpenSandboxは、これらの課題に対し、以下の技術的アプローチとアーキテクチャで解決策を提供します。

1.  **Firecrackerベースの高速・セキュアなサンドボックスランタイム**:
    *   **マイクロVMによる隔離**: 各AIエージェントの実行環境は、AWSが開発した軽量仮想化技術であるFirecrackerを基盤とするマイクロVMとしてプロビジョニングされます。これにより、従来のコンテナよりも高いセキュリティ分離（カーネルレベルでの分離）と、従来のVMよりもはるかに高速な起動性能（P50で64ms、10並行でP99で125.4ms）を両立します。
    *   **一時停止と再開**: サンドボックスはメモリとディスクの状態を保持したまま一時停止・再開が可能です。これにより、エージェントの評価や強化学習において、環境の再初期化にかかる時間を大幅に短縮し、計算リソースを効率的に利用できます。

2.  **AIエージェント向けの高レベルな実行環境API**:
    *   **コマンド実行とファイル管理**: サンドボックス内でシェルコマンドの実行、ファイルの読み書き、スクリプトの実行といった基本的な操作を、SDKを通じて直感的に行えるAPIを提供します。
    *   **ブラウザ/デスクトップ環境**: PlaywrightやChrome、さらには完全なデスクトップ環境をサンドボックス内で実行する機能を提供し、AIエージェントによるWebオートメーションやGUI操作を可能にします。

3.  **統一されたライフサイクルAPIとKubernetes統合**:
    *   **ローカルからクラスターへ**: Dockerでのローカル開発環境から、Kubernetesクラスターへの大規模デプロイメントまで、サンドボックスの作成、管理、破棄を一貫したAPIで提供します。
    *   **Kubernetesオペレーター**: Kubernetesネイティブなオペレーターを通じて、サンドボックスのリソースプール管理、バッチ作成、ライフサイクル管理を自動化し、エージェント評価や強化学習トレーニングといった高負荷ワークロードを効率的に処理します。

4.  **厳格なネットワークアクセス制御**:
    *   **イングレスゲートウェイ**: 統一されたイングレスゲートウェイを通じて、サンドボックスへのインバウンドトラフィックを安全にルーティング・管理します。
    *   **エグレスポリシー**: サンドボックスごとにカスタマイズ可能なエグレスポリシーを適用し、エージェントがアクセスできる外部ネットワークリソースを厳密に制御することで、データ流出や不正アクセスを防止します。

5.  **Credential Vaultによる安全な資格情報管理**:
    *   AIエージェントが外部サービス（例: SaaS API、データベース）にアクセスする際に必要な認証情報（APIキー、トークンなど）を、サンドボックス環境に直接公開することなく、安全に注入・利用できるメカニズムを提供します。これにより、機密情報の漏洩リスクを最小限に抑えます。

6.  **広範なSDKサポートと拡張性**:
    *   Python, Java/Kotlin, TypeScript/JavaScript, C#/.NET, Goといった主要なプログラミング言語向けのSDKを提供し、多様な開発スタックからの統合を容易にします。
    *   CLIツール `osb` は、サンドボックスの作成、コマンド実行、ファイル操作、診断、ネットワークポリシー管理といった一般的なワークフローをコマンドラインから直接実行できる機能を提供します。
    *   MCP (Multi-Agent Communication Protocol) のサポートにより、Claude CodeやCursorのようなMCP対応のAIエージェントクライアントとのシームレスな連携を可能にします。
    *   サンドボックスのライフサイクルおよび実行APIは公開されており、特定の要件に合わせたカスタムランタイムや機能拡張を構築するための基盤を提供します。
