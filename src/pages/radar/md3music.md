# md3Music: 概要と革新性

`md3Music` は、GitHubで858以上のスターを獲得している注目のオープンソースプロジェクトです。Dart言語で書かれたFlutterフロントエンドと、高性能なRust製バックエンドを組み合わせた、次世代のAndroid音楽プレイヤーとして開発されています。その名の通り、Googleの最新デザインシステムであるMaterial Design 3 (MD3) と、Apple Musicの洗練されたユーザーエクスペリエンスを融合させた、モダンで美しいUIが特徴です。

このプロジェクトは、中国の主要音楽サービス「酷狗音楽」のAPIをベースに構築されており、オンライン音楽の検索、再生、管理から、ローカル音楽ファイルの再生まで、幅広い機能を提供します。特に注目すべきは、組み込みのRust APIサーバーを採用している点です。これにより、外部サーバーを別途用意することなく、アプリケーション単体で全てのAPIリクエストをローカルで処理できるという、革新的なアーキテクチャを実現しています。

## 解決する主要な課題とアーキテクチャ

`md3Music` が解決する主要な課題は、既存の音楽プレイヤーが抱えるパフォーマンス、リソース消費、そしてプライバシーに関する懸念です。

1.  **外部サーバー依存の排除とプライバシーの向上:** 多くのサードパーティ製音楽プレイヤーは、APIリクエストを処理するために外部サーバーに依存しています。`md3Music` は、Rustで実装された軽量なAPIサーバーをアプリ内に組み込むことで、この外部依存を完全に排除。全てのAPIリクエストがローカルの `127.0.0.1` で処理されるため、ユーザーデータのプライバシーが強化され、ネットワーク遅延の影響も最小限に抑えられます。
2.  **高性能・低リソース消費:** Rustは、その高いパフォーマンスとメモリ安全性で知られています。従来のNode.jsベースのAPIサーバーと比較して、Rust製サーバーはメモリフットプリントが大幅に削減され、起動時間も高速化されています。これにより、Androidデバイス上での音楽再生体験がよりスムーズかつ効率的になります。
3.  **リッチなユーザーエクスペリエンス:** Flutterの表現力豊かなUIフレームワークを活用し、Material Design 3とApple Musicのスタイルを融合した美しいインターフェースを提供。多音質選択（標準、高質、無損、Hi-Res）、USB独占出力、DLNA投屏、Apple Musicスタイルの逐字歌詞表示、さらには魅族Flymeデバイス特有の状態欄歌詞表示など、ユーザーの音楽体験を向上させるための豊富な機能が盛り込まれています。

**アーキテクチャ概要:**
*   **フロントエンド:** Flutter (Dart) で構築されたUI層。Androidのネイティブ機能（JNI/MethodChannel）を通じてRustサーバーと連携。
*   **バックエンド:** アプリケーションに組み込まれたRust製APIサーバー (`libkugou_server.so`)。`tiny_http` と `ureq` を利用し、酷狗音楽APIへのリクエスト処理、キャッシュ、暗号化などをローカルで実行。
*   **データ層:** ローカルデータとキャッシュ管理にはSharedPreferencesとSQLiteを使用。
*   **プラットフォーム連携:** USB独占出力にはネイティブC++ (JNI/CMake) を、DLNA投屏には`dlna_dart`ライブラリを使用するなど、高度なプラットフォーム機能も統合。

## 競合ツール/商用SaaSとの徹底比較

`md3Music` は、そのオープンソース性、技術スタック、そしてユニークな機能セットにより、既存の商用音楽プレイヤーやSaaSとは一線を画します。

| 特徴/項目          | md3Music (OSS)                                     | 商用音楽プレイヤー/SaaS                                |
| :----------------- | :------------------------------------------------- | :----------------------------------------------------- |
| **ライセンス**     | GNU AGPL-3.0 (オープンソース)                      | プロプライエタリ (サブスクリプション/購入)             |
| **APIサーバー**    | アプリ内組み込みRustサーバー (外部サーバー不要)    | クラウドベースの集中型サーバー (外部依存)              |
| **パフォーマンス** | Rustによる高性能・低リソース                     | サーバー側の負荷やネットワーク状況に依存               |
| **プライバシー**   | APIリクエストをローカル処理、データ管理の透明性  | ユーザーデータが外部サーバーに送信される可能性           |
| **カスタマイズ性** | ソースコード公開、完全なカスタマイズが可能         | 制限的、APIやSDKの範囲内でのカスタマイズのみ           |
| **UI/UX**          | MD3 & Apple Musicスタイル、動的取色、豊富なテーマ  | ブランド固有のデザイン、カスタマイズ性は低い場合が多い |
| **独自機能**       | USB独占出力、DLNA投屏、Flyme状態欄歌詞、逐字歌詞   | 一般的な機能に限定、特定のニッチ機能は少ない           |
| **コスト**         | 開発・運用コストは自己負担、ライセンス費用なし     | サブスクリプション費用、追加機能は有料                 |

`md3Music` の最大の強みは、その透明性とカスタマイズの自由度です。AGPL-3.0ライセンスの下で、開発者は自由にコードを改変し、特定のニーズに合わせて機能を拡張できます。また、Rustによる高性能なローカルAPI処理は、ネットワーク環境に左右されにくい安定した体験を提供し、プライバシー意識の高いユーザーにとって大きな魅力となります。

## インストール & クイックスタート手順

`md3Music` をローカルでビルド・実行するための基本的な手順です。

### 前提条件

*   **Flutter SDK:** 3.47.0+
*   **Dart SDK:** 3.12.0+
*   **Rust:** 1.70+ (Rustサーバーを再ビルドする場合)
*   **Android NDK:** 28 (Rustクロスコンパイル用)
*   **開発環境:** Android Studio / VS Code

### 手順

1.  **プロジェクトのクローン:**
    ```bash
    git clone https://github.com/zzyoxml/md3Music.git
    cd md3Music
    ```
2.  **Flutter依存関係のインストール:**
    ```bash
    flutter pub get
    ```
3.  **Rustサーバーのビルド (オプション):**
    `libkugou_server.so` は既にリポジトリに含まれていますが、Rustコードを変更した場合は再ビルドが必要です。
    ```bash
    cd kugou_api_server/rust
    ./build_android.sh # Android向けクロスコンパイル
    cd ../../
    ```
4.  **アプリケーションの実行 (デバッグモード):**
    Androidデバイスを接続し、以下のコマンドを実行します。
    ```bash
    flutter run
    ```
5.  **リリース版APKのビルド:**
    ```powershell
    .\scripts\md3.ps1 android
    ```
    これにより、複数のABI（arm64-v8a, armeabi-v7a, x86_64）に対応したAPKが `build/app/outputs/flutter-apk/` に生成されます。

**商用利用の可否:**
*   **可能です。** AGPL-3.0は商用利用を禁止していません。
*   ただし、以下の重要な義務が発生します。

**ライセンスの主な義務:**
1.  **ソースコードの公開:** `md3Music` を改変して配布する場合、その改変されたソースコード全体を、AGPL-3.0の下で公開しなければなりません。
2.  **ネットワーク経由でのサービス提供:** AGPL-3.0の最大の特徴は、ソフトウェアをネットワークサービスとして提供（SaaSとして利用）した場合でも、そのサービスを利用するユーザーに対して、改変されたソースコードを要求に応じて提供する義務が生じる点です。これは、従来のGPLが「配布」に限定されていたのに対し、「ネットワーク経由での利用」もカバーするよう拡張されたものです。
3.  **ライセンス表示の維持:** オリジナルのライセンス表示、著作権表示、免責事項を維持する必要があります。

**ビジネス上の考慮事項:**
*   **受託開発:** クライアント向けにカスタマイズする場合、その改変コードはAGPL-3.0で公開する必要があります。クライアントがプロプライエタリなコードを望む場合は、このライセンスモデルが障壁となる可能性があります。事前にクライアントとの合意形成が不可欠です。
*   **SaaS提供:** `md3Music` をベースにした音楽サービスをSaaSとして提供する場合、サービスを利用するユーザーが要求すれば、そのサービスの基盤となっている改変されたソースコードを提供しなければなりません。これは、ビジネスモデルや知的財産戦略に大きな影響を与えるため、慎重な検討が必要です。

AGPL-3.0は、オープンソースコミュニティへの貢献を強く促すライセンスであり、その特性を理解し、適切に遵守することで、透明性の高いビジネスモデルを構築することが可能です。
