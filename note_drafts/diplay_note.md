## 主な機能とアーキテクチャ概要

DiPlayは、KotlinおよびAndroid NDK（C++）スタックで構成され、以下の機能をすべてソフトウェア単体で完結させます。

- **完全ソフトウェアエミュレーション**: 外付けドングル不要。USB有線接続およびWi-Fi Direct / 車載AP / 既存LAN経由のワイヤレスCarPlay接続。
- **車両ハードウェア直接連携（HUD / CAN-Bus）**: 車両のメータークラスタやヘッドアップディスプレイ（HUD）に交差点案内・ストリート名をリアルタイム投影。
- **超低遅延・高音質ストリーミング**: `MediaCodec`ハードウェアアクセラレーションによるH.264映像デコード、Opus/AACソフトウェアジッターバッファリング。

## 商用カスタマイズ・実装の勘所（コピペで使える設計ガイド）

商用案件でDiPlayを安定稼働させるための、実務で検証済みのキオスク化構成ファイルおよびスクリプトです。

### 1. 車載Android起動時 自動プロビジョニング・ADBスクリプト
車両のACC電源ONと同時にDiPlayをデーモンとして安定起動し、画面スケール不整合を自動修復するシェルスクリプトです。

```bash
#!/system/bin/sh
# ========================================================
# DiPlay Commercial Kiosk & Display Resolution Watchdog
# ========================================================

PACKAGE_NAME="com.shihab.diplay"
MAIN_ACTIVITY="com.shihab.diplay.MainActivity"

# 1. 必要なセキュアパーミッションを付与
pm grant $PACKAGE_NAME android.permission.WRITE_SECURE_SETTINGS
pm grant $PACKAGE_NAME android.permission.SYSTEM_ALERT_WINDOW

# 2. Wi-Fi Direct用ポートおよびバックグラウンド実行の最適化
dumpsys deviceidle whitelist +$PACKAGE_NAME
appops set $PACKAGE_NAME RUN_IN_BACKGROUND allow

# 3. リバースカメラ後の解像度リセット（BYD DiLink 4.0/5.0 特有バグ対策）
CURRENT_DENSITY=$(wm density | awk '{print $NF}')
if [ "$CURRENT_DENSITY" != "240" ]; then
    wm density 240
fi

# 4. アプリ起動確認（立ち上がっていない場合は再起動）
if ! pidof $PACKAGE_NAME > /dev/null; then
    am start -n $PACKAGE_NAME/$MAIN_ACTIVITY --ez auto_connect true
fi
```

### 3. ライセンス遵守と法務上のセキュリティ境界
DiPlayのライセンスは**GPL-3.0**です。ここを取り違えると商用展開時に致命的なトラブルとなります。

1. **GPL汚染を避けるアーキテクチャ境界**:
   - DiPlay本体のAPKを修正して顧客の独自業務ロジックを直接埋め込むと、開発した全コードの公開義務が発生します。
   - **対策**: 顧客向け業務アプリ（配車管理・点呼システム等）は独立した別APKとして開発し、DiPlayとは**Android Intent / AIDL / Local Broadcast**を介して疎結合で連携させてください。この方式であれば、自社業務アプリをプロプライエタリ（非公開・著作権保護）のまま保持できます。
2. **Apple MFiおよび商標に関する注意**:
   - 提案書やWebサイト上で「Apple公式認定」「CarPlay公式互換ユニット」と記載することは商標侵害・虚偽表示リスクがあります。「Android車載機向けオープンソースプロトコルブリッジ導入支援」と定義することが実務上の鉄則です。
