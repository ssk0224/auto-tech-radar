## はじめに：なぜ今、世界中で爆発的に注目されているのか？

「ChatGPTを導入したが、社内チャットや顧客対応で炎上や誤送信が怖くて現場が使えない」
「生成AIに返信を書かせると、相手の機微や皮肉を読み違えてトンチンカンな回答を出してしまう」

企業の現場で生成AI導入が踊り場を迎えている最大の原因は、**「書く能力」の不足ではなく、「相手の意図とリスクを看破する能力」の欠如**にあります。

いまGitHubで急速にスター数を伸ばし、海外の開発者コミュニティで話題を独占しているのが **「jev-chat-jarvis」**（jev-chat）です。

このOSSの思想は極めて明快かつ実用的です。
**「いきなり返信を書かない。まず相手の真意とリスクを判定し、人間が選んだ1手だけを入力欄に流し込む。送信ボタンを押すのは常に人間である。」**

本記事では、このjev-chatのアーキテクチャを活用し、**「企業のカスタマーサポート部門や営業チーム、経営層向けに80万〜250万円のAI導入・受託開発案件」**を即座に受注するためのビジネスモデル、商用提案書、見積工数、そして安全に本番稼働させるためのAPI中継Docker構成キットを完全公開します。

## 主な機能とアーキテクチャ概要

jev-chat-jarvisは、Kotlin（Android）を中心に、Windows、macOS、iOS向けに展開されているマルチプラットフォームの意思決定アシスタントです。

1. **画面内テキストの非侵襲的キャプチャ**: アクセシビリティAPIやオンデバイスOCRを用い、チャットアプリのAPI制限を受けることなく画面上の対話を取得。
2. **2段階LLMプロンプティング（Judge & Draft）**:
   - Step 1: 相手の発言の「意図（本音）」「リスク度（炎上・コンプライアンス）」「真の課題」を特定。
   - Step 2: その分析に基づき、トーンの異なる3〜4種類の返信案を生成・ランキング。
3. **ワンタップ入力・人間送信（Strict Human-in-the-loop）**: AIがチャットを勝手に送信する事故を物理的に遮断。
4. **完全なBYOK（Bring Your Own Key）構造**: ベンダー側の中継サーバーを持たず、企業のセキュアなプライベートLLMエンドポイントに直接接続可能。

### 3. `app.py` (ゲートウェイ本体：コピペで動作)
```python
import os
import json
from fastapi import FastAPI, Header, HTTPException, Depends
from pydantic import BaseModel
from openai import OpenAI

app = FastAPI(title="Jev Chat Enterprise Gateway")

API_TOKEN = os.getenv("GATEWAY_API_TOKEN", "default-insecure-token")
client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL")
)
MODEL_NAME = os.getenv("MODEL_NAME", "gpt-4o-mini")

def verify_token(authorization: str = Header(...)):
    token = authorization.replace("Bearer ", "")
    if token != API_TOKEN:
        raise HTTPException(status_code=401, detail="Unauthorized token")
    return token

class AnalyzeRequest(BaseModel):
    conversation_history: list[dict] # [{"role": "user/assistant", "text": "..."}]
    latest_message: str

@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/v1/chat/judge-and-draft")
def judge_and_draft(req: AnalyzeRequest, token: str = Depends(verify_token)):
    system_prompt = """
    あなたはチャットコミュニケーションの意思決定支援AIです。
    相手のメッセージを分析し、以下のJSON形式で回答を出力してください。
    
    【出力JSONフォーマット】
    {
      "intent": "相手の真の意図（簡潔に）",
      "risk_level": "LOW | MEDIUM | HIGH",
      "risk_reason": "リスクの理由（なければ空文字）",
      "suggested_actions": ["推奨する方針1", "方針2"],
      "draft_replies": [
        {"tone": "丁寧・標準", "reply": "返信案1"},
        {"tone": "共感・配慮", "reply": "返信案2"},
        {"tone": "簡潔・断り/境界線設定", "reply": "返信案3"}
      ]
    }
    """

    user_content = f"【会話履歴】\n{json.dumps(req.conversation_history, ensure_ascii=False)}\n\n【最新メッセージ】\n{req.latest_message}"

    try:
        response = client.chat.completions.create(
            model=MODEL_NAME,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_content}
            ],
            response_format={"type": "json_object"},
            temperature=0.3
        )
        result = json.loads(response.choices[0].message.content)
        return result
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
```

### Q1. 「AIが勝手にお客様へ間違ったメッセージを送ってしまう心配はありませんか？」
**【回答トーク】**
> 「ご安心ください。本システムは一般的な自動応答ボットとは根本的に思想が異なります。AIには『メッセージの送信権限』を一切与えていません。AIの役割は、画面上に相手の意図と炎上リスクを可視化し、入力ボックスに候補文を『下書きとして流し込む』ところまでです。最後の送信ボタンを押すのは、100%人間のオペレータです。これにより、誤送信リスクを物理的にゼロにしつつ、思考工数を7割削減します。」

### Q2. 「社内の機密情報や顧客とのチャット内容が外部のAI企業に漏洩しませんか？」
**【回答トーク】**
> 「jev-chatアーキテクチャの最大の強みは、クラウドベンダーへ会話ログが保存されない『ダイレクト通信』にあります。さらに今回ご提案する構成では、自社VPC内に中継ゲートウェイを構築し、個人情報（電話番号、氏名、口座情報等）をリアルタイムでマスキングした上で、学習に利用されない商用API（Azure OpenAI等）へ送信します。第三者にデータが蓄積されるリスクは完全に排除されます。」
