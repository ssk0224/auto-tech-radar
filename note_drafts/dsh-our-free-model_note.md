## 主な機能とアーキテクチャ概要
「dsh-our-free-model」は、DeepSeek Harness (dsh) のプラグインとして動作し、以下の主要な機能とアーキテクチャ的特徴を備えています。

*   **開箱即用（Out-of-the-box）:** インストールするだけで、アカウント登録やAPIキー設定なしに、すぐに最先端AIモデルを利用開始できます。この手軽さが、AI導入の障壁を劇的に下げます。
*   **多モデル統合:** DeepSeek V4.1 Flash、Kimi K3といった無料モデルに加え、NVIDIA NIM、OpenRouter、Groq、Geminiなど、76社ものプロバイダーを「聚合渠道」として統合。単一インターフェースで多様なモデルを管理・利用できます。
*   **データプライバシー:** AI利用状況（トークン消費、応答速度など）のデータは全てローカルマシンに保存され、外部への送信は一切ありません。機密情報を扱う企業にとって、これは極めて重要なメリットです。
*   **OpenAI/Anthropic互換ローカルゲートウェイ:** 本プラグインは、OpenAIおよびAnthropicのAPIと互換性のあるローカルゲートウェイを提供します。これにより、既存のAIツールやアプリケーションから、統一されたAPI形式で「dsh-our-free-model」が提供するモデル群を呼び出すことが可能になります。
*   **高度なトークン削減:** ツール出力の圧縮（RTK）、プロンプトの軽量化、特定のクエリに対するローカル応答など、AI利用の効率を最大化し、無駄なリソース消費を防ぐための機能が組み込まれています。
*   **柔軟なルーティング（降級チェーン）:** 複数のAIモデルを組み合わせて、フォールバック（障害時の代替）やラウンドロビン（負荷分散）といった戦略的なルーティングを実装できます。これにより、常に最適なモデルを安定して利用することが可能になります。
*   **アプリ内アップグレードとホットリロード:** プラグインの更新やコード変更が、アプリケーションの再起動なしに即座に適用されます。運用中のダウンタイムを最小限に抑え、常に最新の機能を利用できます。

### 実務でそのまま使える設定ファイル例 (settings.json)

「dsh-our-free-model」の設定は、dshのプロファイルディレクトリ内の`settings.json`に保存されます。以下は、商用利用で特に重要となる設定項目とその例です。

```json
{
  "probeIntervalMinutes": 15, // モデルの可用性検出間隔（分）。デフォルト30分。商用では短縮推奨。
  "defaultMaxTokens": 8192,   // デフォルトの最大出力トークン数。モデルの能力に合わせて調整。
  "forward": {
    "enabled": true,          // ローカル転送（OpenAI互換API）の有効化
    "listenAddress": "127.0.0.1", // 転送APIのリスニングアドレス。セキュリティのためローカルホストに限定推奨。
    "listenPort": 18899,      // 転送APIのリスニングポート。
    "apiKey": "sk-your-secure-local-api-key" // ローカルAPIキー。外部ツールからのアクセスに必要。
  },
  "streamRecovery": {
    "enabled": true,          // 長思考後のストリーム回復機能の有効化。安定性向上に寄与。
    "maxRecoveryAttempts": 1, // 回復試行回数。デフォルト1回。
    "recoveryTimeoutSeconds": 300 // 回復試行のタイムアウト（秒）。
  },
  "tokenSaver": {
    "enabled": true,          // トークン削減機能の有効化。
    "prompts": {
      "caveman": "off",       // プロンプト軽量化（caveman族）の強度。off/lite/full/ultra/wenyan-lite/wenyan/wenyan-ultra
      "ponytail": "off"       // プロンプト軽量化（ponytail族）の強度。off/lite/full/ultra
    },
    "rtk": {
      "enabled": true         // ツール出力圧縮（RTK）の有効化。git diff, grep結果などを圧縮。
```

### 拡張コード例（Pythonでのローカルゲートウェイ利用）

ローカルゲートウェイを有効にすることで、Pythonなどの言語からOpenAI SDK互換でAIモデルを呼び出すことができます。

```python
import openai

# dsh-our-free-modelのローカルゲートウェイ設定
# settings.jsonで listenAddress: "127.0.0.1", listenPort: 18899, apiKey: "sk-your-secure-local-api-key" を設定済みとする
LOCAL_GATEWAY_BASE_URL = "http://127.0.0.1:18899/v1"
LOCAL_GATEWAY_API_KEY = "sk-your-secure-local-api-key" # settings.jsonで設定したAPIキー

client = openai.OpenAI(
    base_url=LOCAL_GATEWAY_BASE_URL,
    api_key=LOCAL_GATEWAY_API_KEY,
)

def chat_with_ai(prompt: str, model_id: str = "our-free-model/deepseek-v4-flash-free"):
    """
    dsh-our-free-modelのローカルゲートウェイ経由でAIとチャットする関数
    """
    try:
        response = client.chat.completions.create(
            model=model_id,
            messages=[
                {"role": "system", "content": "あなたは優秀なAIアシスタントです。"},
                {"role": "user", "content": prompt}
            ],
            max_tokens=1024,
            temperature=0.7,
            stream=True # ストリーミング応答を有効にする
        )

        print(f"AI ({model_id}): ", end="")
        full_response_content = ""
        for chunk in response:
            if chunk.choices[0].delta.content:
                print(chunk.choices[0].delta.content, end="", flush=True)
                full_response_content += chunk.choices[0].delta.content
        print("\n")
        return full_response_content

    except openai.APIConnectionError as e:
        print(f"API接続エラー: {e}")
    except openai.APIStatusError as e:
        print(f"APIステータスエラー: {e.status_code} - {e.response}")
    except Exception as e:
        print(f"予期せぬエラー: {e}")
    return None

if __name__ == "__main__":
    print("dsh-our-free-model ローカルゲートウェイ経由AIチャットテスト")
```

### 社内運用時のセキュリティ境界、アクセス権限管理、ライセンス遵守の注意点

*   **セキュリティ境界:**
    *   **ローカルゲートウェイのアクセス制御:** `settings.json`の`forward.listenAddress`を`127.0.0.1`に設定することで、APIアクセスをローカルマシンに限定できます。LAN内の他のマシンからのアクセスを許可する場合は、`0.0.0.0`に設定し、ファイアウォールでアクセス元IPアドレスを厳密に制限してください。
    *   **局域网转发中继:** LAN内からのアクセスを許可する機能ですが、必ず信頼できるネットワークでのみ有効化し、独立した中継キーを厳重に管理し、定期的にローテーションしてください。
    *   **APIキーの保護:** `settings.json`は0600権限で保存されますが、ファイルシステムレベルでのアクセス制限を徹底し、不必要なユーザーからのアクセスを防いでください。
*   **アクセス権限管理:**
    *   dsh自体のユーザー管理機能と連携し、プラグインへのアクセス権限を適切に設定します。
    *   ローカルゲートウェイのAPIキーは、利用するアプリケーションやチームごとに発行・管理し、定期的なローテーションを義務付けることで、不正利用のリスクを低減します。
*   **ライセンス遵守:**
    *   「dsh-our-free-model」自体はMITライセンスであり、商用利用、改変、再配布が自由です。しかし、本プラグインが利用する**上流プロバイダー（OpenCode, Kilo AI, 聚合渠道経由の各プロバイダー）には、それぞれ独自の利用規約が存在します。**
    *   特にKilo AIの無料チャネルでは、**プロンプトがサービス改善のために記録される可能性がある**と明記されています。機密情報を扱う場合は、この点に十分注意し、必要に応じて利用を避けるか、クライアントに明確に説明する必要があります。
    *   商用利用の際は、各AIモデルのライセンスや利用制限も確認し、遵守することが不可欠です。
