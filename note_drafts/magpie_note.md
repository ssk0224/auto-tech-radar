## 主な機能とアーキテクチャ概要

magpieの本質は、**「すべてのAIエージェントの通信を束ねる、超軽量なローカル/オンプレミス型リバースプロキシ」**です。

1. **プロトコル完全自動変換**
   - Claude Code（Anthropic形式）、Cursor（OpenAI形式）、Gemini CLI（Google形式）などの差異を吸収。どのエージェントからでもDeepSeekやローカルOllama、あるいはChatGPTサブスクを透過的に呼び出せます。
2. **スマート・ルーティング（Smart, Pace, Usage）**
   - 複数アカウントを登録しておけば、更新期限が近いクォータを自動消費させたり、使用率の低いアカウントへ自動フェイルオーバー。開発者はAPI切れに一切気づくことなく作業を継続できます。
3. **Intent Routing（意図解釈ルーティング）**
   - 開発者の指示を小型モデルが瞬時に解析。「簡単なコメント付けやタイポ修正」は100万トークン数円の格安モデルへ、「大規模リファクタリング」はClaude 3.5 SonnetやOpusへ自動配分します。

## 商用カスタマイズ・実装の勘所（コピペで使える設計ガイド）

### 1. Docker Composeによる社内集中型magpieサーバー構築

全社員の端末に直接設定させるのではなく、社内ネットワーク（またはVPN）内に共通ゲートウェイを立てる場合の `docker-compose.yml` 定義です。

```yaml
version: '3.8'

services:
  magpie-gateway:
    image: ghcr.io/yetone/magpie:latest
    container_name: enterprise-magpie
    restart: always
    ports:
      - "3425:3425"
    environment:
      - MAGPIE_HOST=0.0.0.0
      - MAGPIE_PORT=3425
      - MAGPIE_NO_ACCOUNTS=1 # サーバー運用時はローカルKeychain探索を無効化
      - DO_NOT_TRACK=1       # 社内規定に配慮しテレメトリを完全遮断
    volumes:
      - ./data:/root/.config/magpie
      - ./plugins:/root/.config/magpie/plugins
    networks:
      - dev-internal

networks:
  dev-internal:
    driver: bridge
```

### 2. 機密情報マスク＆モデル名リライト用Bunミドルウェア

magpieの強力なプラグイン機能を利用し、リクエストに含まれる機密情報を自動マスキングしつつ、モデル指定を強制マッピングするミドルウェア例です（`./plugins/enterprise-guard.js`）。

```javascript
// enterprise-guard.js
// 登録: magpie plugin add ./enterprise-guard.js

export function onRequest(body, ctx) {
  // 1. モデル名の自動ルーティング（コスト最適化）
  // 開発者が "default-fast" を指定した場合は格安の DeepSeek にリライト
  if (body.model === "default-fast") {
    body.model = "deepseek/deepseek-chat";
  }

  // 2. 機密情報（APIキー、秘密鍵、JWT）の簡易検知とマスキング
  if (Array.isArray(body.messages)) {
    body.messages = body.messages.map(msg => {
      if (typeof msg.content === 'string') {
        let content = msg.content;
        // AWS Access Key ID のマスキング
        content = content.replace(/(A3T[A-Z0-9]|AKIA|AGPA|AIDA|AROA|AIPA|ANPA|ANVA|ASIA)[A-Z0-9]{16}/g, "[REDACTED_AWS_KEY]");
        // 秘密鍵ブロックのマスキング
        content = content.replace(/-----BEGIN [A-Z ]+PRIVATE KEY-----[\s\S]*?-----END [A-Z ]+PRIVATE KEY-----/g, "[REDACTED_PRIVATE_KEY]");
        return { ...msg, content };
      }
      return msg;
    });
  }

  return body;
}

export function onResponse(response, ctx) {
  // レスポンスヘッダーやログ用のメタデータを注入
  return response;
}
```

### 3. 社内運用時のセキュリティ境界と権限管理

- **LAN共有時の個別トークン発行**:
  magpieの設定で `Share on local network` を有効にし、社員またはプロジェクトごとに個別キーを発行します。
  ```bash
  # プロジェクトA専用キー（日次コスト上限付き）を発行
  magpie token create project-alpha --max-cost-daily 10.0
  ```
- **ライセンス管理の注意点**:
  magpie本体はMITライセンスのため、社内改変や自社サーバー運用に関して法的なリスクは皆無です。ただし、**「各LLMプロバイダ（OpenAI, Anthropic等）の利用規約」**において、個人向けProアカウントを多人数でスクレイピング/プロキシ共有する行為は規約違反（ToS違反）となる可能性があります。
  受託開発で企業に導入する際は、必ず**「正規のAPIキー（従量課金）」または「Team / Enterpriseプラン」**の認証情報を使用するよう設計・提案してください。
